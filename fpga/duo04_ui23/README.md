# TangLab UI23：浅色双手乐器界面

按用户提供的四页示意图实现 FPGA HDMI UI。以已验证 IO22 / `554124f` 为基线，现有 RTL 只改动 `duo04_panel.v`、`duo_fan.v`；IMU、音频、事件、菜单按键逻辑与原版相同。工程：`tanglab_duo04_ui23.gprj`，顶层 `top_duo04`，器件及原始 50 MHz / 25 MHz 时钟约束不变。

## 页面

- 双手演奏：米白卡片、暖金背景；左手橙红、右手金橙；5/7/12 音区的 180° 半环；音色、真实力度、操作手、总音量与运行状态。
- 真实击发：接收每手实际击发计数的变化，原击发扇区高亮约 150 ms，并显示击发音名。移动预选不会制造击发；停止、离线或切页清除高亮。
- 快捷与设置：左侧固定六分组和快捷入口，右侧显示当前菜单、当前值、编辑与二次确认。音色、音阶、八度、音效等用中文语义值显示。
- 逐音等待教学：目标金色、正确绿色、错击红色；当前目标手、1–16 步进度、正确/错击计数；完成后显示练习完成。
- 诊断与归中：两手独立的在线、归中及可演奏/待归中/越界/精度不足等状态，显示当前操作手。

图上的样例数值只用于 RTL 仿真。`preview/index.html` 可浏览实际像素输出的页面截图，包含十二音、五音、编辑、复位确认、停止与离线等变体。

## 操作保持当前程序口径

| 操作 | 功能 |
|---|---|
| KEY0 短按 | 当前手归中；菜单中确认 |
| KEY0 长按 | 当前手换音阶；菜单中返回 |
| KEY1 / KEY2 短按 | 主视图换音色 / 切操作手；菜单中加 / 减 |
| KEY2 长按 | 当前手设置 |
| KEY0+KEY1 | 完整设置 |
| KEY1+KEY2 | 演奏或教学 / 诊断切换 |
| KEY0+KEY2 | 全局停止 |
| EC11 | 主视图旋转调音量、短按开菜单；菜单中选择/调值、短按确认、长按返回 |

没有采用参考图中“教学页 KEY0 开始/暂停”的提示，实际 KEY0 保持归中；开始/暂停仍在快捷菜单。在线 IMU 仍按已归中方向选区、负本体 Z 去重力加速度或急动度击发。

## 低资源实现

固定 640×480 输出，由字模 ROM、扇区扫描线 ROM、32×40 手形和 128×24 标志单色 ROM、坐标与调色板实时绘制，没有整屏帧缓存，也没有合成三角函数。文字使用项目已有霞鹜文楷等宽 Medium 的 16×16 单色字模，音名使用较紧凑的 ASCII 字距；主屏不堆放姿态和通信计数。

有效 ROM 位数记录在 `ui23-assets.json`。这些是逻辑数据量，实际 BRAM/LUT 和功耗必须查看本轮综合/布局布线结果。没有实测功耗结论，也没有新增自动分辨率协商。

## 重建与验证

1. `python generate_ui23.py <LXGWWenKaiMono-Medium.ttf路径>` 重生成字模和静态掩模。可使用项目 `docs/reference/fonts/` 中的原字体，许可见 `OFL-WenKai.txt`。
2. WSL / Linux 安装 Icarus 后执行 `bash run_ui23_tests.sh`：真实计数击发、按键、EC11、教学、停止五项语义测试，以及十四个完整 640×480 栅格状态。
3. Gowin 1.9.12.03 执行 `gw_sh.exe build.tcl`。算法 1 延续既有 IO22 选定策略，本 UI23 版本还需独立取得最终时序结果。
4. 使用源码快照、当前实际综合网表、六个 IMU 开漏管脚、完整 setup/hold 和音频管脚报告验收，再进入 SRAM 验证。不能用 IO22 的通过报告证明 UI23。

硬件连接沿用 IO22：两路独立 I²C，EC11、HDMI、板载 PT8211 和标准 I²S 输出管脚均不变。具体见 [实板说明](BOARD_VALIDATION.md)。


## 本轮综合与工具兼容

文字地址的常数乘法改为等价移位加法，规避 Gowin 1.9.12.03 的 SP00019/10ATO32 推断内部错误。16384 组完整地址范围对照通过；布局、字符和输出像素保持等价。

| 整工程综合项 | IO22 基线 | UI23 |
|---|---:|---:|
| LUT | 47210 | 48259 |
| 寄存器 | 30539 | 31020 |
| BSRAM | 117 | 112 |
| MULT12X12 | 9 | 6 |

以上为综合计数，不能代替实际布局布线占用或功耗。两手 IMU、音频、控制及 CST/SDC 均沿用已验证基线。
