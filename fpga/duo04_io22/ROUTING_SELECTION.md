# 路由策略如何选定

当前实现按最终时序质量选择路由算法，而不以编译耗时决定下载版本。

1. 算法2和算法1顺序执行，使用相同RTL、ROM、工程、管脚及时钟约束。工具在独立工程中会自动重新综合，因此各候选的实际网表分别校验。
2. 任一候选必须通过源码哈希、网表来源、位流生成、管脚、50 MHz核心/25 MHz像素时钟和全部setup/hold违例检查。
3. 两者都通过时，选择最差setup裕量更大的结果；报告精度下相同时，再比较hold裕量和CLS占用。完全相同时采用器件默认算法2。
4. 两者都未通过则停止发布，继续修复实际时序路径。

算法1增加搜索时间，并不保证每个设计都有更好的结果。算法2是本器件的工具默认值。依据：本机Gowin V1.9.12.03文档 `SUG100-4.4.6E`，印刷页39（PDF第51页）。

`compare_routes.py`只读取完成的报告并选择结果，不启动EDA或下载器。默认要求网表完全相同；当前实现明确使用独立综合模式，仍要求RTL、ROM、工程和约束完全相同，各候选必须通过自己的网表哈希、接口与时序检查。不能把独立综合结果的差异单独归因于路由参数。`test_route_selection.py`检查不同输入、失败结果、负裕量和结果相同时的处理。

完成后，`validation/routing-comparison/selection.json`记录实际指标与位流哈希，`build_selected.tcl`复现选定的路由策略。`build.tcl`仍提供器件默认算法2的快速完整构建入口。

路由结果不能证明真实功耗、温升、DAC兼容性或整机延迟；这些项目需要实板测量。
