# DUO04-LIVE 2.2：I²S 与 IMU 延迟优化

基于 GitHub `e9230db` 的 DUO04-LIVE 2.1 FPGA 快照；仅修改 FPGA。独立工程 `tanglab_duo04_io22.gprj`，器件 GW5AST-LV138PG484AC1/I0。旧版本与旧位流仍保留。

## 音频接口

- 板载 PT8211 保持原来的 48 kHz / 16 位 LSBJ 时序。
- 新增并行 Philips I²S：48 kHz、16 位有效数据、每声道 16 位槽、BCLK=1.536 MHz（32fs），WS=0 左声道 / 1 右声道，WS 比下一声道 MSB 提前一个 BCLK。
- 二者共用一个采样时基、锁存同一对左右采样，不添加整帧缓存。**没有 MCLK**。外接 DAC 必须明确支持上述格式；要求 64fs、32 位槽或外部 MCLK 的 DAC 不能直接假定兼容。
- 标准 I²S 只连接外接 DAC 的数字输入，不接 PT8211 原引脚。I²S 数字输出已补齐，赛方对整机接口的最终验收仍需确认，并提供外接 DAC 实机结果。

| 新输出 | FPGA 球位 | Dock 长排针 | 连接 |
| --- | --- | --- | --- |
| i2s_bck | C14 | J13.4 | DAC BCLK/SCK 输入 |
| i2s_ws | B13 | J13.5 | DAC WS/LRCLK 输入 |
| i2s_dout | C13 | J13.6 | DAC DIN/SD 输入 |
| 共地 | GND | J13.12 | DAC GND |

这些位置在旧 DUO03 中是踏板/腕部按键输入，**下载本版本前，断电移除这些旧接线及其他主动驱动设备**。基线 DUO04 2.1 未使用三脚。J13.11 是 **5 V**，不是 3.3 V；DAC 按自身规格供电，信号为 LVCMOS33。引脚依据 NEO Rev1.4 原理图 p7/19 及原仓库 DUO03 追踪表，不按照片左右定位。

## IMU 请求配置

| SH-2 报告 | 原间隔 | 新间隔 | 请求频率 |
| --- | --- | --- | --- |
| 0x04 线性加速度（击发） | 10 ms | 2.5 ms | 400 Hz |
| 0x08 六轴姿态 | 10 ms | 5 ms | 200 Hz |
| 0x02 陀螺仪 | 10 ms | 5 ms | 200 Hz |
| 0x01 原始加速度 | 10 ms | 20 ms | 50 Hz |
| 0x06 重力 | 10 ms | 20 ms | 50 Hz |

各手仍使用独立 I²C 总线，地址 0x4A。50 MHz 核心时钟下 `HALF_DIV=65`：低电平至少 1.30 µs，高电平从观察到 SCL 上升后计时，保留时钟拉伸；实际时钟低于 384.6 kHz 上界，满足 BNO085 最大 400 kHz 和 tLOW≥1.3 µs。不能换为对称 HALF_DIV=63 以逼近 400 kHz，那会让低电平过短。

Roll/Pitch 表情滤波与报告节拍检查同步改为 200 Hz，击发使用真实时间戳计算急动度，仍要求负本体 Z 去重力加速度或负向急动度。归中、数据失效保护、有限重试和禁用后的开漏释放保留。

**以上是请求值，不是传感器实测值。** BNO085 手册指出实际支持的离散报告速率与请求可能不同，且各类报告不能都同时取最大速率。必须用真实报文时间戳和线性加速度有效脉冲检查实际周期、连续序号与积压；底层 `report_rates` 接口仅包含姿态/原始加速度/陀螺仪，不包含线性加速度；最新版诊断UI也不能替代线性报文速率测量。不要把其中任一项当成线性加速度频率。

## 延迟与验证边界

详见 `validation/RESULT.json` 和仿真日志。数字验证包括：旧 PT8211 波形逐周期对比、独立 I²S 接收、50 MHz 原速 I²C 从机、混合报告速率、归中和负 Z 急动度击发、32 Voice 合成/现有音效/增益/串行输出，以及 200 Hz 表情频带。

采样相位等待的设计预算由 0～10 ms 降为 0～2.5 ms（前提：实测达到 400 Hz）。模型中最大报文从准备好到线性加速度译码约 1.721 ms；指定负向急动度样例到 note_on 约 1.240 ms。独立音频样例 note 接收到首个非零串行位约 0.089 ms。它们是分段仿真，不是同一次实测，也不是覆盖所有音色/相位/负载的整机上界。

传感器内部融合/滤波、真实调度及打包、总线电容与拉伸、实际音色起音、DAC/模拟链路都需要计入实测。HDMI 画面另有帧等待，不能用屏幕点亮时间代替声音延迟。**尚未证明整机 ≤10 ms 或进阶 ≤5 ms；没有在此版本上下载/测量硬件。**

## 复现

Windows 安装同版本 Gowin 后，在本目录执行 `gw_sh.exe build.tcl`。Linux/WSL 安装 Icarus 后运行 `bash run_regressions.sh`；扩展测试编译命令见 `run_io_tests.sh`。仿真未缩放生产 50 MHz 音频/总线时钟；混合 IMU 仿真仅缩短上电复位/启动等待，不强制内部校准状态。

默认交互回归包含本轮完成的九项测试；I/O 与表情四项运行 `bash run_io_tests.sh`。完整 UART 长测试需显式执行 `RUN_LONG_UART=1 bash run_regressions.sh`，其未完成状态不包含在本轮通过结论中。`python check_implementation.py` 只核对保存的源码、位流、时序与管脚证据，不会启动下载器。

新位流必须结合本次源文件哈希、布局布线报告与 manifest 核对后下载，不能拿旧版本的报告当成 2.2。板载 PT8211 可先验证；外接 DAC 未连接时，I²S 三根输出留空。

实板步骤见 [BOARD_VALIDATION.md](BOARD_VALIDATION.md)，其中区分当前2.1按键操作、真实采样周期、I²S格式与整机延迟测量。

## 构建速度优化

之前脚本强制 `route_option 1`。随 Gowin 安装的《SUG100-4.4.6E》印刷第39页（PDF第51页）明确说明：算法1牺牲编译速度改善布线，算法2提高布线速度；GW5A(S)(T)-138 系列默认值为2。本项目现在使用器件默认算法2。

| 入口 | 用途 |
| --- | --- |
| `gw_sh.exe build.tcl` | 默认：完整综合及算法2布局布线 |
| `gw_sh.exe pnr_only.tcl` | RTL、ROM、工程输入未改动时，复用本地综合网表，只运行算法2布局布线 |
| `gw_sh.exe build_quality.tcl` | 显式选择较慢的算法1，供后续需要时比较 |

本轮通过文件哈希确认 RTL 与综合网表完全一致，复用综合结果的依据保存在 `validation/netlist_reuse.json`。`pnr_only.tcl` 还会检查输入修改时间，找不到网表或输入更新时停止。发布验收继续检查源码哈希、网表来源、实际路由算法、50 MHz 时序、保持时间及管脚；快速构建也必须通过这些检查。

本轮仅调整构建流程，沿用13项已通过的RTL仿真记录。实际提速倍数与最终时序需待新布线报告确认，不能由算法选项直接推算。

## 2026-10-19 时序修复

首轮布线实际核心 Fmax=49.073 MHz，50 MHz 建立时间最差裕量 −0.378 ns、407 个违例端点；该位流未作为通过版本发布，失败报告保存在 `validation/timing-attempt01/`。

- 菜单限幅先比较常量阈值，再执行加减，去掉串联的加法器与比较器。
- 表情开关摘要和普通远程菜单动作寄存；参数写入先锁存字段与值，下一拍写参数库。停止命令直接生效并冲掉待写队列。
- 操作模式到事件来源的选择寄存；切换的一拍内两路事件都暂停消费，原取消握手继续有效，包含进入教学时同时启动的情况。
- 音高配置分开计算 ROM 地址、读取系数和乘法，增加两拍（50 MHz 下 40 ns）。修订号在地址锁存时记录；若表情在查表期间变化，会保留脏标志并再次更新，背压时数据保持不变。

新增测试验证查表期间改变弯音不会漏更新，以及无效参数、远程动作与数据配对、停止冲掉排队启动、来源切换期间的事件背压。32 声部最大渲染仍为 674 核心周期。实际时序结果待构建完成核验；没有降低工作频率或新增宽泛的假路径。

中间一次综合在 ROM 推断阶段触发 `gwsyn.dll` 崩溃；改为独立时钟块中的同步 ROM 读取后，缩小的调度器工程已综合通过。该检查不能替代整工程布局布线。

## 验证说明

测试基于 Icarus：`tb_ui21_panel` 使用等价的归约异或与 case 相等判断未知像素，规避该模拟器对 `$isunknown(拼接表达式)` 的误报（曾报 RGB=182a3e 为未知）。可见区额外检查字形索引和字体行无 X；没有为通过测试修改生产 UI。

`tb_io22_uart` 沿用2.1真实921600串行协议与音频路径，但固定无关的视频时钟来加速事件仿真；HDMI另外运行九状态完整栅格检查。它不验证物理串口、PLL、TMDS或模拟DAC。诊断页静态“2.1交互版”字样沿用新版UI，新增I/O版本由HELLO `DUO04-LIVE 2.1+IO22` 和位流哈希识别。

SH-2线性/姿态报告序号和时间戳连续性单独验证；继承的SHTP通道sequence_gaps计数可能包含四字节探测与续传造成的序号跨越，不能据其单独判断传感器漏采样。本轮未改变此统计口径。

本轮未重复运行继承的四音色长时间波形采集 `tb_duo04_audio`：音色DSP字节未改，已运行32声部与生产输出链路回归；长波形/频谱验收保留原版本证据与后续实机任务，不能算作2.2新实测。

I²S独立按左/右顺序串行化，PT8211保留右/左顺序，两者共享同一时刻锁存的采样对；不是只改变WS而复用同一根数据流，以避免I²S左右错一采样。姿态选区请求周期为5ms，击发线性加速度为2.5ms，两项等待预算应分别考虑。

完整教学/512点抓取UART长回归未在本轮跑到结束，不计通过。协议字段与抓取存储布局沿用2.1；本轮实际执行的是新HELLO的921600位级仿真、现有主机解析器/CRC与能力识别、命令边界流水线检查、按键/菜单/教学单位测试，以及独立音频输出验证。`tb_io22_uart`保留供后续完整回归。
