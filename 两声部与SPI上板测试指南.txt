Tang Mega 138K 普通 Dock（C 版本）——两声部＋SPI IMU 上板指南
配套：TangLab.exe、TangLabCtl.exe、fpga/bitstream/tanglab.fs、board-test 参数文件
目的：下午上板验证上位机、数字音频与 SPI 数据通路。当前未做实物测试。

一、准备（先不要接 IMU）
1. 将整个分享 ZIP 解压到可写目录，例如 D:/TangLab。不要只提取 EXE，也不要在压缩包里运行。
2. 确认板卡是 Tang Mega 138K 普通 Dock、C 版，不是 Pro、60K 或其他芯片版本。
3. 准备可传数据的 USB 线、3.3 V 逻辑的 GY-BNO085、杜邦线和耳机/有源音箱。
4. 安装板卡 USB JTAG/UART 驱动、Gowin EDA 与 Programmer。软件不包含 EDA 本体和许可证。
5. 本次固件复用已完成综合布局布线的四声部测试工程，仅预设启用两声部；不是重新编译的“两声部专用芯片”。
   编译依据与 SHA256 见 board-test/固件清单.json。四声部能力保留，不能把两声部通过当成比赛 ≥4 复音验收。

二、断电接线（确认位置后再上电）
以下是普通 Dock 的 PMOD0，位号 J9；编号按官方 31005 原理图。
打开 docs/reference/dock_31005.pdf 第 19 页核对排针，找板上 1 脚标记。
表格只表示引脚编号，不代表你面对板卡时的上下左右；不确定方向时先不要通电。

J9 脚号     FPGA 管脚     接 GY-BNO085 丝印       用途
1           3V3          VCC_3V3                电源正极，接 3.3 V
3           GND          GND                    共地
11          P19          SDA/MISO/TX            SPI MISO（模块输出）
12          R19          SCL/SCK/RX             SPI SCK
9           T21          AD0/MOSI               SPI MOSI（模块输入）
10          U21          CS                     低有效片选
7           P16          INT                    低有效中断
8           R17          RST                    低有效复位
5           R18          PS0                    FPGA 控制 WAKE；复位时为高
2           3V3          PS1                    选择 SPI

模块 VCC_3V3 按用户提供资料为一个电源脚，2.4～3.6 V，推荐 3.3 V；不要接 5 V。
PS0 接 J9-5 后不能再硬接 3.3 V，否则 FPGA 拉低唤醒时会冲突。
J9-6/T18 是可选控制事件标记，不要接到 IMU；其余未使用排针留空。
这些 PMOD 管脚已经被工程占用，不要同时接其他扩展模块。所有改线必须断电。
SPI 模式为 Mode 3（时钟空闲高）、默认 1 MHz。CS/INT/RST/PS0 都要接。

三、检查时钟与调试 USB
1. 按板卡官方方式供电，USB 数据线接标为 USB JTAG/UART 的调试接口，不是其他 USB 数据接口。
2. 查看设备管理器，记下真实 USB 串口 COM 编号。com0com 是电脑虚拟串口，不能选它代替板卡。
3. 本工程 FPGA 时钟输入是 V22，约束 50 MHz，来自板载 MS5351。
   若你曾改过调试器时钟设置，先在板卡配套调试器工具中恢复此时钟输出为 50 MHz。
   本上位机不配置 MS5351；不要通过改串口波特率来掩盖时钟不匹配。
   可用示波器或逻辑分析仪核对实际时钟。握手返回的 50 MHz 是固件声明，不是频率计测量。

四、SRAM 下载（先确认固件与器件匹配）
1. 打开 Gowin Programmer，选择板卡调试线缆/USB JTAG，扫描设备。
2. 应识别 138K C 版器件；配套工程型号为 GW5AST-LV138PG484AC1/I0。
   若显示其他型号，停下来检查板卡，不能强行下载此文件。
3. 在器件配置中选择 SRAM 编程操作（英文界面名称含 SRAM Program），文件选择：
   本文件夹/fpga/bitstream/tanglab.fs
4. 点击执行/下载，等待成功状态；失败时先检查供电、驱动、线缆和器件识别。
5. SRAM 下载掉电失效，断电后重新下载。初次不要选择烧写 Flash，避免覆盖原有启动内容。
6. 下载成功后默认静音；没有声音不代表下载失败，下一步需发送声部参数。

五、上位机握手（不用 agent 也能做）
1. 双击 TangLab.exe，刷新串口，选真实板卡 COM，点击“连接 FPGA”。
2. 观察状态：应显示真实 FPGA 数据来源、握手成功和固件版本；不是“模拟演示”。
3. 软件固定使用 921600 baud；未握手前不发送声部或 IMU 命令。
4. 若 5～10 秒仍未成功：确认固件下载、实际时钟、COM 和串口占用，再断开重连。

六、先手动验证两个声部
1. “声部与包络”页设置：
   声部一：375 Hz，增益 0.12，正弦，勾选发声。
   声部二：750 Hz，增益 0.12，正弦，勾选发声。
   声部三、四：取消发声。
   四路起音 10 ms，衰减 80 ms，持续电平 0.7，释音 180 ms。
2. 点击“应用四个声部”，等待完成。耳机/音箱接 Dock 音频输出，音量从低开始。
3. “音频示波器”选立即触发，点击“抓取 2048 点”。正常现象：
   声部一/二是不同频率的波形，声部三/四接近零，混音是两路叠加。
4. 单击声部一放大；开启时间游标，把两线放在相邻峰附近，周期应约 2.667 ms。
   声部二周期约 1.333 ms。用幅值游标读幅值差，不要把混音周期当成所有声部频率。
5. 取消某路发声并应用，等待约半秒再抓取：该路应静音，另一路继续。
6. “频谱分析”选混音，主要峰应在 375 和 750 Hz 附近。分辨率为 48000/2048≈23.4375 Hz。
   相位以片段起点为参考，不是传感器延迟；弱频点相位被屏蔽是正常的。
7. 点击“全部松键/释音”结束试听。实际听音需要你确认，自动程序只能检查数字采样。

七、再手动验证 SPI IMU
1. 确认已经按第二节接线；“IMU 三接口”选择 SPI Mode 3 · 1 MHz。
2. 点击“设置接口并复位 IMU”，等待约 2 秒，再点击“应用报告配置”（100 Hz）。
3. 先看配置应答，再看姿态/加速度/角速度计数是否持续增加；FPGA ACK 不等于 IMU 配置成功。
4. 静置时姿态基本稳定；慢慢转动小板，应看到姿态改变、角速度响应；加速度包含重力。
5. 点击归中验证软件零位；查看原始报文区域应有持续数据。
6. 没有报告：断电检查 PS1、PS0、CS、INT、RST，以及 MISO/MOSI 是否接反。
   必要时观察 SCK、CS 和 INT；不要把 SPI 线直接改接 5 V，也不要带电换线。

八、使用 agent 或命令工具跑完整数字流程
先停止当前记录。GUI 保持打开，点“07 agent 调试”→“开启本机接口”。
在 TangLab 文件夹空白处打开 PowerShell，依次执行：

  .\TangLabCtl.exe status
  .\TangLabCtl.exe ports

若 GUI 已握手成功，直接运行：

  .\TangLabCtl.exe run test.two_voice_spi --file .\board-test\two-voice-spi.json

不要在真实测试时使用 simulation.json。若还没连接，可先在 GUI 选择 COM 并连接，最不容易输错。
希望全部由命令连接时，运行以下命令并输入设备管理器中的实际 COM：

  $boardPort = Read-Host '输入实际板卡 COM 编号'
  @{port=$boardPort} | ConvertTo-Json | Set-Content -Encoding UTF8 .\board-test\本机连接.json
  .\TangLabCtl.exe run connect --file .\board-test\本机连接.json

自动流程依次完成：握手能力查询、声部一单独、声部二单独、双声部、双路静音、
完整抓取/频谱/混音检查、SPI 复位配置、三类报告各收集至少 1000 条、一次往返测量、记录及回放一致性。
SPI 采集最长等 120 秒；记录回放也需要原记录时长，总流程可能数分钟。
期间可操作缩放和游标，但不要重复排队连接、参数或记录命令。新硬件命令会排在当前任务之后。
取消：在 agent 页点“取消当前命令”。自动流程仍尝试停止记录、关闭预览和四路松键。
设备断线时不能保证松键成功，按板上复位或断电静音。取消上升过零等待不等于固件已撤销抓取。
本次流程独立验证声部和 SPI，没有“转动 IMU 改变音调”的 FPGA 映射。

无板卡，仅检查软件自动流程：
  .\TangLabCtl.exe run test.two_voice_spi --file .\board-test\simulation.json
结果必须标明模拟，SPI 为未执行，不能作为比赛实测证据。

Codex 桌面版和 Claude Code CLI 的完整提示词及命令参数在 docs/agent调试接口说明.md。
把当前 TangLab 文件夹作为 agent 工作目录即可；agent 不要另开串口，也不要打印会话令牌。

九、保存结果与人工功能清单
命令完成后 JSON 的 result.directory 是结果目录，也可在 agent 页点击“打开测试结果目录”。
自动结果位于 agent-results/日期时间-随机编号：
  测试结果.txt / 测试结果.json：逐项结论、实际计数、失败原因与测量条件。
  仅声部一.csv / 仅声部二.csv / 双声部.csv / 双路静音.csv：五通道样本。
  采样.csv / 幅相谱-0～4.csv / 统计.json：双声部阶段分析；最终 IMU 和延迟在测试结果.json。
  recording：原始报文和会话信息，可在主窗口打开回放。
自动回放检查在独立解析器中进行，不抢板卡串口；手动“打开回放”会断开真实板卡。

有时间再逐项手动点一下（不用重新编译固件）：
□ 分栏/叠加、独立缩放、单击放大/恢复正常。
□ 五路时间/幅值游标可独立开关，复位后出现在视窗内。
□ 右键中文菜单、网格、平移/框选、图片导出可用。
□ 预览包络持续更新，暂停只冻结画面；恢复完整抓取后可看幅相谱。
□ CSV、幅相谱及统计导出路径正确，回放来源标为文件回放。
□ IMU 姿态、归中和计数随真实转动变化。
□ Gowin 页可选择实际安装目录、打开工程编辑器和下载工具；外部原始日志允许英文。
□ agent status、reports、spectrum、job 查询得到与 GUI 同一来源的数据。
□ 实际耳机/音箱能听到音调，松键后声音结束。
将人工检查结论另记到结果目录，不要改自动报告中的原始计数。

十、结果怎么解释
通过：本次数字数据满足检查条件；模拟通过必须同时看 source/simulated 标记。
失败：查看细节，例如波峰错位、串口 CRC/丢帧、配置没应答或报告数量不足。
待人工确认：真实听音、接线目检等需要你操作。
未执行：没有硬件、没有外部仪器，或本次范围没有覆盖。
总线耗时、FPGA 封包耗时和 PC 往返不等于完整控制到模拟音频延迟。
比赛 ≤10 ms、≥4 复音、完整双手姿态乐器仍需后续专门验收，不用本次两声部结果代替。
