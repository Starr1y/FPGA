# 双手 I²C 核心与事件所有权

更新：2026-10-11。当前可下载版本仍为单手、静音 **FAN04**。本次增加的 `fpga/dualhand/` 是已通过数字仿真的开发核心，尚无板卡顶层、第二路引脚约束或下载位流，双手 HDMI 尚未接入；数字音频集成见 [双手音频说明](双手数字音频集成与验证.md)，FAN04 位流未变。

## 已完成的程序

两手各有一条独立 I²C 总线，均可使用 BNO085 地址 `0x4A`。每条链路独立完成传感器配置、报告解析、姿态换算、归中、选区、负 Z 击发与 Roll/Pitch 表情；复用冻结的 FAN04 模块，默认核心时钟 50 MHz。

| 文件 | 作用 |
| --- | --- |
| `fpga/dualhand/rtl/bno_i2c_hand.v` | 一手的完整传感器到演奏控制链路 |
| `fpga/dualhand/rtl/two_hand_i2c_core.v` | 两条独立链路及事件出口 |
| `fpga/dualhand/rtl/two_hand_event_queue.v` | 每手独立 FIFO、轮流输出、取消与释放屏障 |
| `fpga/tools/check_dual_hand.py` | 无需板卡或上位机的 Icarus 仿真入口 |

每手可独立设置 7/5/12 布局、归中和表情使能。镜像反转相对偏航和横滚，保留俯仰及模块自身负 Z 击发；切换镜像后只重新归中该手。

## 事件与取消协议

默认每手 FIFO 深度 8，同时击发分别入队，接收端 `event_ready` 控制出队。等待接收时保持事件数据稳定；满队列丢弃新事件并累加该手的丢弃计数，不能保证无限阻塞时无损。

| `event_data` 位 | 含义 |
| --- | --- |
| 63:32 | 该手当前 epoch，取消旧演奏后递增 |
| 31:30 | 0=击发，1=力度补充更新 |
| 29 | 手编号，0/1 |
| 28:25 | 音区索引，完整 4 位，保留十二区的 8～11 |
| 24:23 | 布局编号，沿用 FAN04 |
| 22:21 | 有符号八度偏移 |
| 20:14 | 7 位力度 |
| 13:12 | 1=加速度，2=急动度，3=同时满足 |
| 11:4 | 该手局部事件编号 |
| 3:0 | 保留，零 |

音频接收端必须使用 **手编号、epoch、事件编号** 识别事件和力度更新。复位、重新归中、掉线、停用或镜像改变时清除该手旧队列，设置 `release_pending[hand]`；接收端释放该手旧 Voice 后返回 `release_ack[hand]`，再接收其新事件。取消优先于同周期 ACK。另一手可继续出队。

原独立 I²C 测试中 `release_ack` 由仿真接收端返回；新增 `two_hand_instrument_core` 已由真实数字 Voice 分配器返回 ACK，关闭该手实际音频 gate 后进入 Release，尾音可继续衰减。epoch 为 32 位，达到最大值后自然回绕。

## 状态接口与板卡接入边界

`status[255:0]` 为手 0，`status[511:256]` 为手 1，各手字段如下：

| 每手位 | 含义 |
| --- | --- |
| 0～7 | 在线、归中完成、归中中、击发就绪、可演奏、越界、漂移、姿态新鲜 |
| 9:8 / 11:10 / 17:12 | 精度 / 归中状态 / 归中进度 |
| 21:18 / 25:22 | 预选区 / 上次击发区 |
| 27:26 / 29:28 | 击发布局 / 击发原因 |
| 30 / 31 | 表情有效 / 通信故障 |
| 47:32 / 63:48 / 79:64 | 映射后的偏航 / 俯仰 / 横滚 |
| 95:80 / 111:96 / 119:112 | 弯音 / 颤音 / 明亮度 |
| 127:120 / 159:128 | 力度 / 击发次数 |
| 175:160 / 191:176 | 包计数 / 字节计数 |
| 223:192 / 255:224 | 协议错误 / 复位尝试 |

报告率、处理丢弃、队列丢弃及取消计数另有独立接口。向量中手 0 总在低位。`calibrate`、`force_reset` 应输入单周期脉冲，表情键为保持电平。

`scl_low`、`sda_low`、`reset_low` 是“请求拉低”的布尔信号，**不是已分配的物理引脚**。板卡适配必须实现开漏：请求拉低时输出 0，否则高阻释放；禁止直接把这些值当作推挽输出。停用或故障会释放该手输出。此逻辑没有实际电源检测，不能替代供电有效检测或掉电隔离。第二颗 IMU 的具体引脚仍需依据原理图选择，本说明不提供猜测接线。

## 已验证范围

```powershell
python -X utf8 fpga/tools/check_dual_hand.py
```

结果与源码 SHA256 见 `board-test/dual-hand/validation.json`，4 项均通过：

- FIFO 深度 1、3、8：同时入队、背压稳定、回绕、满队列统计、取消/ACK 优先级、epoch 与健康手继续出队；每项包含 2500 个随机周期及参考队列比对。
- 原生双手测试：通过两组实际引脚电平的行为传感器模型送入 SHTP 包，走真实解析、四元数换算、击发和表情模块；检查各自原点、布局、负 Z 急动度、同时击发和力度更新、十二区索引 10、独立 Roll/Pitch、松键保持、镜像归中，以及左手复位/停收/停用时右手继续工作。

原生测试使用 **1 MHz 仿真核心时钟、100 Hz 姿态报告**，I²C 配置速率上限 250 kHz（状态及同步开销会降低实际速率）。启动、复位和配置等待缩短为测试参数。它不是生产 50 MHz 时序证明，也未覆盖所有硬件故障类型。

尚待完成：板卡顶层及第二路 CST、双手按键和显示、真实两颗 IMU 脱机测试、资源/时序构建，以及数字音频向板卡 DAC 的连接与实测。现有 FAN04 位流及资源数字不代表双手核心的综合占用。
