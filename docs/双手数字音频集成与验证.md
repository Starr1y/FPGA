# 双手数字音频集成与验证

更新：2026-10-12。开发核心已连接两路原生 I²C、姿态/负 Z 击发、事件队列、Voice 分配、振荡器、ADSR 与 PCM 混音。**FAN04 单手静音位流保留，DUO01 双手数字版本已冻结**；新的 [DUO01 板卡工程](DUO01_双手板卡接入与操作.md)已有第二路 CST、HDMI 和 PT8211 代码，已通过时序与 50 MHz/48 kHz 原生数字链路验证，尚未上板。

## 程序连接

```text
两条 I²C 总线 → two_hand_i2c_core → 每手独立事件队列
                                  ↓
                           dual_voice_scheduler
                                  ↓
                   dual_audio_core（振荡器/ADSR/混音）→ PCM
```

组合入口 `fpga/dualhand/rtl/two_hand_instrument_core.v`，默认 32 Voice、50 MHz 核心时钟。板卡适配需要另行提供 48 kHz `sample_tick`、开漏 I/O、按键/踏板去抖与 DAC/HDMI 连接；这里的 `sample_tick` 是时钟使能，不能作为新的时钟域。

`two_hand_synth.v` 也可独立接收上一版事件队列的事件，便于验证传感器与音频边界。所有演奏控制由 FPGA 处理，不需上位机下发 Note-On。

## 音区与模式

保留完整 4 位区索引，默认 C4 基准；八度偏移随每次击发锁存。

| 布局编号 | 音区映射 |
| --- | --- |
| 0，七音 | C D E F G A B，MIDI 60/62/64/65/67/69/71 |
| 1，五音 | C D E G A，MIDI 60/62/64/67/69 |
| 2，十二半音 | C 到 B，MIDI 60～71，含所有升音 |

`chord_mode=0` 为双旋律；`chord_mode=1` 为手 0 和弦、手 1 旋律。手 0 对应左手是接线/界面约定，不由模块自动识别。

七音和弦按所选级数堆叠三度：C-E-G、D-F-A、E-G-B、F-A-C5、G-B-D5、A-C5-E5、B-D5-F5。五音及十二音布局先采用根音、根音＋4、根音＋7 的大三和弦，属于当前默认设计，可由后续菜单扩展。

模式、布局、音色、尾音与八度在接收新击发时取样。改变模式不改写正在发声的音符；已有尾音保留其音高和音色。踏板的物理输入、去抖和菜单仍待接入。

## 每手声部与事件所有权

- 32 Voice 分为两个独立的 16 Voice 池；支持偶数 Voice 数且至少 8，以容纳两组三和弦。单手不能占用另一手空闲池，因此单手上限为 16，双手总上限为 32。
- 优先空闲 Voice，其次选较安静的 Release，再选最旧的活动 Voice。回收时先让旧包络快速渐弱到零，再装载新频率；另一手不被回收。
- 事件按手编号、32 位 epoch、8 位局部编号归属。力度补充更新作用于对应事件的整个和弦，不串到编号相同的另一手。
- 保留每手 Roll 弯音/颤音，Pitch 明亮度独立送给所属 Voice。`dual_audio_core.v` 由桌面版 `fpga/rtl/audio_core.v` 派生（基准副本保存在 `fpga/dualhand/synthdeps/reference_audio_core.v`），增加每 Voice 明亮度输入和空闲期配置握手；旧音频源码和 FAN04 冻结源码未改。
- 取消归中/复位/掉线/停用组时，排队事件由传感器核心取消；分配器关闭该手 Voice 的 gate。等待旧配置及 gate-off 配置被实际音频核心接收后返回释放 ACK。**ACK 表示已进入 Release，不表示尾音已完全消失**。
- 等待配置接收期间保持配置数据稳定，配置修订号防止新变更被旧 ACK 清除。取消期间已经发出的配置先完成握手，然后补发释放配置，避免破坏配置协议。

当前输出是 **16 位单声道混音**，每 Voice 样本另有输出供后续监测；尚未升级为独立立体声/24 位输出，也未接入合唱、混响、延迟。DUO01 将混音经渐入/渐出增益送入 PT8211 的两个声道，默认静音，仍缺实板声音验证。

## 复现和证据

在仓库根目录执行，需要 Python 3 和 Icarus Verilog（Windows 原生或 WSL Ubuntu）：

```powershell
python -X utf8 fpga/tools/check_dual_audio.py
python -X utf8 fpga/tools/check_dual_audio.py --native-only
```

音色依赖和 ROM 从桌面工程固定复制到 `fpga/dualhand/synthdeps/rtl/`；测试运行目录为 `synthdeps/`，避免依赖仓库中不同架构的历史音频源码。日志及全部输入 SHA256 保存在 `board-test/dual-audio/`。

| 仿真 | 实际覆盖 |
| --- | --- |
| `note-map` | 2048 个穷举向量：所有布局/音区/八度/三和弦成员及非法输入 |
| `synth-8`、`synth-32` | 事件队列接实际振荡器/ADSR/混音；同编号两手力度隔离，独立弯音和明亮度，模式与和弦，真实 gate 关闭后 ACK，保留自然尾音，配置背压期间取消，以及本手渐弱回收 |
| `synth-32` | 32 个实际 Voice 同时有效，MIDI 48～79 各不相同，逐个核对频率；50 MHz/48 kHz 数字渲染无欠载；本场景最大 369 个核心周期，即 7.38 µs |
| `native-sensor-audio` | 两组引脚电平的行为传感器发送原生 SHTP 报告，经真实姿态/负 Z 击发生成左手 F-A-C5 和弦及右手十二区索引 10，驱动实际 ADSR/PCM；停用左手后右手通信及音符保持 |

前两类音频测试是 **50 MHz/48 kHz 数字事件注入**。原生传感器全链路使用 **1 MHz/2 kHz 渲染使能**、100 Hz 传感器报告和缩短的启动/复位等待，仅证明数字连接与所有权，不能作为生产 48 kHz 全系统性能依据。对应两份清单分别为 `validation.json`、`native-validation.json`，不可混用测试频率。

最大渲染周期只描述本仿真场景中的数字计算，**不是动作到 DAC 的延迟**。尚无实板声音、频谱测量、1000 次动作延迟、真实两颗 IMU 或最大效果负载验证；DUO01 已完成独立综合/时序检查；已有 FAN04 12.6% Logic 数字不能套用于双手音频核心。
