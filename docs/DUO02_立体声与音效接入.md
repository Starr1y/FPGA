# DUO02 立体声与音效接入

2026-10-12。独立开发工程 `fpga/duo02/tanglab_duo02.gprj`，顶层 `top_duo02`。整机数字仿真、重建和时序检查已通过，冻结位流为 `fpga/bitstream/tanglab_duo02.fs`，清单为 `board-test/duo02/firmware.json`。**本版本尚未下载或进行实板音频验证**。DUO01 和 FAN04 继续保留各自冻结文件。

## 实现连接

```text
两手 I²C / 各自归中、前方 180° 选区、负 Z 击发
  → 每手事件队列 → 两个独立 16 Voice 池
  → 各自振荡器 / ADSR → 24 位累加 → 移位、16 位饱和
  → 左右独立音效 RAM → 静音增益渐变 → PT8211 双声道
```

左手 Voice 0～15 混入左声道，右手 Voice 16～31 混入右声道，属于硬声像分配。单手在耳机中只出对应声道；目前没有声像旋钮。每手独立 24 位累加，32 Voice 时每路总和右移三位并饱和为 16 位；传统单声道监测数据仍提供给测试，但 DAC 使用的是两个独立输出。

音色、所有权、事件 epoch、组释放和负 Z 击发沿用 DUO01。判断为 `az ≤ −2.5 m/s²` **或** `jz ≤ −80 m/s³`，使用已去重力的本体坐标加速度。没有恢复距离积分选区，也没有将本体 −Z 改为世界竖直向下。

## 音效参数

每声道默认 16384 个 16 位历史采样，左右独立。四个混响抽头在时钟周期中依次读取，共用各自缓存；不使用整屏帧缓冲或存储整首 PCM 音乐。

| 模式 | 本版板端预设 |
| --- | --- |
| 旁路 | 干声逐位通过音效级，湿声目标为零 |
| 延迟 | 4800 采样，48 kHz 时 100 ms，反馈 96/256 |
| 合唱 | 基准 576 采样（12 ms），约 ±96 采样调制、左右 LFO 相差 90°、分数插值，反馈为零 |
| 简化混响 | 基准 3840 采样（80 ms），四抽头平均，反馈 80/256 |

声道缓存独立，模式和湿声配置共用。旋转编码器或外部参数菜单尚未接入，本版延迟/深度/反馈取上表固定预设；独立 `stereo_fx` 模块仍支持可变参数。

湿声设置为 32/64/96/128/160/192/224，分母为 256；界面显示截去小数的 12/25/37/50/62/75/87%。这是湿声比例，不是系统音量。默认旁路、湿声设置 128、通信关闭、声音静音。

请求新模式后先逐采样降低湿声，到零才切模式并清除两路旧历史，再渐增到新目标。湿声每采样最多变化 1/256；切换 224/256 至另一模式并恢复最久约 9.35 ms。它用于控制效果切换突变，不能替代实物听音和爆音测量。

静音增益放在效果之后，每采样改变 1/256，完全渐入/渐出约 5.33 ms。接口和数字输出仍运行，静音末端 PCM 为零且功放关闭。复位、重新归中、停用或故障/掉线时，清除对应手的旧湿声历史，另一手历史保留；干声 Voice 仍按组 Release 自然释放。

## 按键与界面

原 DUO01 的各手操作、静音和和弦组合保留，接线也保持一致，见 [DUO01 接线与按键](DUO01_双手板卡接入与操作.md)。新增：

| 三键操作 | 松开后动作 |
| --- | --- |
| KEY0＋KEY1＋KEY2 短按至少 50 ms、少于 2 秒 | 湿声设置增加一档，224 后回到 32 |
| 三键同时长按至少 2 秒 | 旁路 → 延迟 → 合唱 → 混响 → 旁路 |

第三键稍晚按下时，从三键同时按住起重新计时；组合消耗原来的单键/双键动作。松键先后差异不会额外启停通信、换音色或归中。

界面顶部显示已经生效的效果、目标湿声比例；请求与生效模式不同时显示 `*`。旁路时湿声实际为零，屏幕仍保留下一次效果使用的湿声设置。左右状态新增“等待数据”“回位等待”“重新归中”，区分陈旧报告、防连击/未静稳回位及原点跳变保护。

## 当前证据

生产尺寸音效至 DAC 的独立检查已通过：50 MHz / 48 kHz，4800 采样延迟的有符号左右脉冲、左路历史清除保持右路回声、湿声归零切模式、旧反馈不泄漏至新混响、静音增益和实际 PT8211 串行字。此场景解码 30289 个字。

完整 8/32 Voice 加默认混响至实际串行 DAC 的检查通过，32 Voice 场景共 3034 个采样、6066 个串行字、最大合成 369 周期，没有欠载或效果丢样。14 张 RTL 模拟画面和按键检查通过。50 MHz/48 kHz 原生双传感器整机仿真也已通过：两个 100 Hz 行为 IMU、独立归中、负 Z 和弦/旋律、解除静音后启用混响、渐入渐出和单手停用隔离；解码 83449 个 PT8211 串行字，其中 7960 个非零，本场景最大合成 129 周期。原生场景使用部分声部，32 Voice 满载由前一个独立场景覆盖，不能混用这两个最大周期。

首次 Gowin 构建在布线算法 2 的末尾报 `PR0004: total 0 unrouted nets`，没有进入时序分析或生成位流。失败证据保存在本地 `board-test/duo02/iteration0/`；没有冻结或下载。按本机官方 SUG1220-2.0E 第 37～38 页的选项说明，改用 `set_option -route_option 1`，保持时序驱动、50/25 MHz 约束和严格发布检查，本次重建成功，位流已通过源码、数字检查、引脚和时序匹配后冻结。首次异常根因尚未确定，不能仅凭“0 未布通”当作成功。

重建使用同一版本 RTL；setup/hold 违例为零，核心/像素 Fmax 为 **50.026/26.542 MHz**（实际约束 50/25 MHz）。核心余量约 **0.052%**，非常小；改动或换工具环境后必须重新检查。PR1014 通用时钟路由告警保留。Logic 49437/138240（35.8%）、Register 21989/139095、BSRAM 74/340、DSP 83/298。位流 SHA256 为 `2875c715b1bab84e3e427295e7fe4742cd5c297e43b7fafd92e15d2b79409e13`。**不沿用 DUO01 的 35% Logic 或时序结果作为 DUO02 结果**。数字通过不代表模拟声音、两颗模块、真人动作识别率、漂移、1000 次端到端延迟或两小时满负载运行已经通过。
