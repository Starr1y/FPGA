# 双声道音效开发与验证

2026-10-12。模块 `fpga/effects/rtl/stereo_fx.v` 已完成独立仿真与综合，**DUO01 保持原样；已在 DUO02 中生成冻结音效板卡位流，尚未实物听音**。后续独立 [DUO02](DUO02_立体声与音效接入.md) 已复制该模块并接入左右混音、模式切换和静音渐变，整机检查、构建和时序门槛已通过并冻结。此模块推进任务书 T3，不代表完整音效系统已经验收。

## 模式和参数

| mode | 功能 | 内部处理 |
| --- | --- | --- |
| 0 | 旁路 | 输出与本次输入逐位相同，后台记录干声历史 |
| 1 | 延迟 | 单抽头反馈回声，反馈上限 192/256 |
| 2 | 合唱 | 左右 LFO 相差 90°，相邻采样线性插值，反馈为零 |
| 3 | 简化混响 | 同一缓存读取 D、约 3D/4、D/2、约 7D/8 四个抽头并平均，反馈上限 128/256 |

这是一种多抽头反馈混响，不能称为真实房间建模。左右缓存独立，没有自动混入另一声道。

- `wet`：0～255，干湿比例的分母为 256；255 时仍保留 1/256 干声。
- `feedback`：按模式限幅，避免环路增益达到 1；写缓存和输出都有有符号 16 位饱和，记录实际削波采样数。
- `delay_samples`：最小 1，最大缓存容量减一。默认每声道 16384 采样，48 kHz 时最大约 341.3 ms。
- `chorus_depth`：调制深度，约 ±0～255 个采样；越过缓存边界时钳位并清除分数部分。
- 默认 LFO 每采样增加 210/2²⁴ 周期，48 kHz 时约 0.601 Hz。相邻抽头插值减少整采样跳变。
- `clear_history[1:0]`：每声道独立清除历史有效计数，已经读入流水线的旧回声也会失效；不逐地址清零 RAM。

输入的声音、模式和参数在 `in_valid && in_ready` 时锁存。单次事务包含八个时钟，接受输入至输出经过七个完整时钟周期，50 MHz 下为 140 ns；这不包含上游 IMU、合成器或 DAC 的等待，不是整机延迟测量。

## 资源结构

左右各一组逻辑 RAM，每组只有一个读端口和一个写端口；四个抽头在不同核心时钟读取，共用缓存；RTL 只在读事务期间更新 RAM 读寄存器，不产生门控时钟。默认容量的 Gowin 综合实测：

| 综合项 | 数量 |
| --- | --- |
| Register | 446 |
| LUT | 720 |
| ALU | 470 |
| MULTALU27X18 | 10 |
| MULT12X12 | 2 |
| BSRAM | 32（每声道 16 个 SDPB 原语） |

BSRAM 占器件 340 个中的约 9.4%。上述是独立模块、所有参数可变化的**未布局综合统计**，不是整个系统最终资源或时序结果。合唱插值和干湿/反馈乘法分在两级流水线，后续集成仍需重新检查 50 MHz 时序。

## 检查与证据

```powershell
python -X utf8 fpga/tools/check_stereo_fx.py
python -X utf8 fpga/tools/synth_stereo_fx.py
```

三个仿真检查已经通过：

1. 逐位旁路、未写入 RAM 不泄漏未知值、左右延迟隔离、反馈衰减、四个混响抽头、单声道/事务中清除、饱和与忙时丢样计数。
2. 90 个有符号合唱样本与独立数值参考逐点比较，验证分数插值、左右相位及运行中参数快照。
3. 默认满尺寸 RAM 的 33000 个采样，最大延迟、两次指针回绕、独立清除和带旧缓存内容复位。

综合检查确认 32 个 SDPB、左右各 16 个；只执行 `run syn`，没有分配板卡引脚或生成 `.fs`。证据保存于 `board-test/stereo-fx/`。

DUO02 已提供独立左右混音、效果后的静音渐变及板端模式/湿声入口，原生整机数字链路已通过；构建/时序已通过；仍需接入完整效果参数菜单、编码器入口及真实音频验证。外部控制与参数菜单目前单独检查并综合通过，已接入独立菜单绘制与帧快照，尚未接入 DUO02/TMDS 或实物。不能把 DUO01 的单声道复制输出描述成独立立体声或已有音效。
