# FPGA 音频波形与频谱采集

2026-10-17。任务书 T4 的波形/频谱采集组件，位于 `fpga/audio_monitor/`。本组件尚未接入 DUO03 的板卡顶层或 HDMI；没有新的可下载位流。DUO03 保持冻结。

## 数据来自哪里

观测点选择音效和静音增益之后、PT8211 之前的 `pcm_valid/pcm_left/pcm_right`。这能显示实际数字输出中的混响尾音和静音渐变。它不是由音符名称合成的演示曲线，也不依赖 PC 计算正式演奏画面。

组件只有 PCM 输入，没有 ready/等待输出，不能阻塞原音频链路。高负载时只丢弃完整观测块并计数，不修改样本。实际音频和观测组件共处整机后的资源、时序与欠载仍需重新验证；组件接口无背压不等于整机实现没有开销。

## 波形和频谱

| 项目 | 实现 |
| --- | --- |
| 输入 | 每次 `pcm_valid` 同时接收左右两个有符号 16 位样本 |
| 分块 | 每声道 1024 点；标称 48 kHz 下每块约 21.333 ms |
| 波形 | 每 16 个原始样本保留最小/最大值，每声道 64 列；不丢掉列内尖峰 |
| 窗 | 对称 Hann，`0.5−0.5*cos(2πn/1023)`，Q1.15 系数 |
| FFT | 1024 点、时域抽取 radix-2，输入位反序，正向指数符号；两声道复用同一运算器 |
| 精度 | 24 位有符号实部/虚部，输入保留 8 位小数，每级右移一位，总归一化 1/1024 |
| 输出频点 | 每声道 0…512，共 513 个复数频点，含 DC 和 Nyquist |
| 标称频轴 | `k*48000/1024`，间隔 46.875 Hz，Nyquist 为 24 kHz |
| 系数 | 本地解析公式生成，无外部 FFT IP；ROM 及参数清单随源码提供 |

FFT 的归一化和频点顺序按[NumPy FFT 官方定义](https://numpy.org/doc/stable/reference/routines.fft.html)核对。ROM 中 +1 无法由 Q1.15 精确表示，因此单位旋转蝶形直接使用原值，避免每级累积 32767/32768 衰减。

这里输出的是已加窗、按 N 归一化、仍带 8 位小数的复数值。不是经过 Hann 幅度补偿的 dBFS，也不是音高识别结果。显示层需明确相对幅度、频率分组和量程；不能把单个 FFT 格子的宽度当作区分任意 32 个邻近音高的保证。

## 缓冲和提交协议

原始立体声使用两块 1024×32 缓冲，变换使用单块 1024×48 工作 RAM。保护中的采集块在两个声道复制和变换结束前不会被新输入覆盖；过载跳过整块，恢复空闲后从下一完整块首重新采集。

- `frame_start`：开始一个观测事务，`frame_id` 是包含丢弃块的原始块序号。
- `wave_valid`：提供 `wave_channel/column/min/max`；列内保持全 16 位原始样本极值。
- `bin_valid`：提供 `bin_channel/index/real/imag`；每声道索引递增。
- `frame_done`：两个声道均完成，消费者才可提交此帧。最后一个频点与完成脉冲可以同周期，需包含该频点再显示。
- 复位时必须丢弃未完成事务，不能把复位前的部分波形拼到新帧。
- `dropped_blocks` 饱和计数；`completed_frames/last_cycles/max_cycles` 用于观测负载。未完成块不得冒充一帧。

该 FFT 的输出接口仍在 50 MHz 域。后续一级 `fpga/audio_scope/rtl/audio_monitor_core.v` 已将其接入双缓冲和垂直消隐提交逻辑，详见下节。Voice 状态页将读取真实 `active/owned/gates/notes/envelopes`，不能从频谱条数推断声部数。

## 已验证内容

数字检查包含静音、正/负 DC、块边界脉冲、整数频点、非整数频点、不同声道双音、满幅交替、满幅台阶及固定种子噪声；另测超额输入负载、恢复及变换中复位。

共 12 个完整立体声帧（其中 9 个为正常 50 MHz/48 kHz 采样节奏），12,312 个复数频点、1,536 个波形列与整数参考逐位一致；独立 NumPy 浮点 FFT 的最大复数误差约 25.653 Q8 单位，即约 0.101 个 PCM 量化单位。过载时保护原块且丢弃整块，复位中止的 20 个部分波形列不计作完成帧。

整块复制、左右变换与输出共 **120836 个 50 MHz 周期，约 2.417 ms**，少于 21.333 ms 的采集块间隔。该数值是观测器处理用时，不能作为动作到模拟音频输出延迟；频谱本来就需等待一个采集窗口。

组件级 Gowin 综合：Register **776**、LUT **543**、ALU **321**、BSRAM **9**、MULTALU27X18 **2**。捕获、工作区和两种系数共 147456 位 RAM。尚未布局布线，没有整机新增占用、Fmax 或功耗结论；不得将其与 DUO03 的最终 Logic 报表直接相加。

真实合成路径检查直接复用未改动的 DUO03 32 Voice 测试，保留其所有权、背压、音效、混音和串行 DAC 断言。两个完整立体声 PCM 块的 2,052 个频点与定点参考一致；4,061 个非零 PCM 值、2,043 个不同左右声道样本，独立浮点最大误差约 6.401 Q8 单位。结果见 `board-test/audio-monitor/synth-path-validation.json`，不是实物声音或 HDMI 记录。

## 像素域整帧缓冲

`audio_monitor_core` 连接实际 FFT 和 `audio_observer_snapshot`，增加 2×512×32 位双时钟 RAM；核心只写当前不可见的那一块，像素域同步发布标志，在消隐请求时选择新块并返回确认。上一帧未接收时丢弃新的显示事务，计入 `skipped_frames`；不改 PCM 或 FFT 处理节奏。

| 每块地址 | 内容 |
| --- | --- |
| 0…63 / 64…127 | 左/右 64 列波形，每字为 max16、min16 |
| 128…191 / 192…255 | 左/右 64 个频段的最大 `abs(real)+abs(imag)`，25 位 |
| 256…287 | 32 Voice：envelope16、MIDI7、active、gate、owned；高 6 位保留 |
| 288…291 | 原始 FFT 块序号、观测处理周期、观测丢块、显示跳帧 |
| 292…511 | 读取返回零，不暴露未初始化 RAM |

频段 0…31 分别使用 FFT bin 1…32，保留低频分辨率；其后每倍频程按 bin 宽度分成八组，到 bin512。它不是等间距半音，也不是严格的对数频轴。幅度用 L1 近似，较欧氏幅度最多高约 3 dB，不标为校准 dBFS。DC 不加入频谱条。

Voice 元数据在 `frame_start` 同时锁存，避免 32 路来自不同时刻；像素域只在完整两手波形和频点、64×2 个频段及全部 Voice/元数据写完后得到发布标志。缺列、频点乱序、写端碰撞或计数不完整时整帧拒绝。上游输出最后一频点的同周期完成脉冲已经覆盖。

本设计使用共同断言的核心/像素复位，复位清除有效标志而不清 RAM。独立复位其中一个域不属于当前接入约定；整机接入时必须保持这一约定。发布数据通过保持稳定的双缓冲与请求/确认跨域，仍需在整机 SDC 和布局布线中约束和检查。

双时钟单元测试以 50/25 MHz、3.7 ns 非对齐相位检查 **3,584 个像素读字**，覆盖不可提前显示、持续读取旧帧、新帧等待接收、坏帧拒绝、32 Voice 同时锁存、复位丢弃部分事务及未写地址零值。

实际 FFT 到缓冲的联动测试按精确平均 48 kHz 输入整数频点、双音、固定种子噪声三组立体声块。25 MHz 像素端按 800×525 周期、消隐位置提交，核对 **1,536 个读字**，波形、64×2 频段、32 Voice 和元数据全部符合参考，FFT 丢块/显示跳帧/无效帧为零。这里尚未绘制 RGB，也未模拟厂商 PLL/TMDS。

组合组件未布局综合：总 Register **2000**、LUT **1666**、ALU **516**、BSRAM **11**、MULTALU27X18 **2**。这包括 FFT、原始音频缓冲、显示双缓冲与元数据；未接 Voice 合成器、HDMI 绘制器或传感器主机。定点有意截位、频段索引有界截位告警保留；数值与像素数据均由参考逐项核对，不靠关闭告警冒充时序通过。

## 复现

正常检查不需要重新生成 ROM。数值检查额外需要 NumPy（本轮 2.3.5），RTL 仿真使用 WSL Ubuntu/Icarus；综合使用 Gowin 1.9.12.03。

```powershell
python -X utf8 fpga/tools/check_audio_observer.py
python -X utf8 fpga/tools/check_audio_observer_path.py
python -X utf8 fpga/tools/synth_audio_observer.py
python -X utf8 fpga/tools/verify_audio_observer.py
python -X utf8 fpga/tools/check_audio_snapshot.py
python -X utf8 fpga/tools/check_audio_monitor_core.py
python -X utf8 fpga/tools/synth_audio_monitor_core.py
python -X utf8 fpga/tools/verify_audio_monitor_core.py
```

只有修改系数公式时才运行 `fpga/tools/gen_audio_monitor_rom.py`；改变 HDL/ROM/测试后需要重新生成对应证据。`audio_observer.gprj` 只用于组件综合，没有板卡引脚或可下载位流。
