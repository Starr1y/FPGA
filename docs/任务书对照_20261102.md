# 任务书对照与未完成项（2026-11-02，V14）

## 对照依据及判定方式

依据仓库[2026-09-23任务书整理稿](任务书_20260923历史整理.md)及其引用的V1.0技术评审任务材料。原始Word原件本轮未找到，因此这是对现有整理稿的逐项技术核查，不宣称已核对新的正式竞赛文件。

历史[执行与验收](当前任务书执行与验收.md)更新于10月17日，含过时的源码现状；其“尚无32Voice”等旧结论不能直接套用V14。这里以V14源码、冻结仿真、完整PNR/STA与本次用户反馈分别判定。未重新运行的历史测试会标明。

用户后续变更：接口改I²C；左传感器改MPU6050、右仍BNO085；IMU只选音，外接按钮击发；显示1024×600；图片简谱教学首版允许电脑参与、无需板端Flash存谱。原任务中的SPI、动作击发、力度、完全脱机教学不能因此直接算通过，需作为变更/降级向验收方说明。

## 当前优先级

1. **先闭环声音**：确认快捷菜单启动→按键事件计数→Voice活动→非零PCM→DAC/耳机输出。当前低电平与音量调整不足以证明事件已到音频。
2. **修方向与区域手感**：记录归中前后Y轴方向、原始/过滤Yaw、选区和校准状态；先复现180°问题，再核查角度缩放/安装轴定义。不能简单整体加180°掩盖。
3. **完成默认音量80的新构建**：当前归档V14默认8；源码、位流、哈希和STA必须作为一个新版本更新，不能只改README称已完成。
4. **下一版双手MPU**：用户已确认下一版改为左/右均MPU6050，并将默认音量设为80。需重新配置、编译和验证两路独立归中、选音、按钮与掉线隔离；本次上传的V14仍是左MPU+右BNO，不使用旧位流冒充双MPU。
5. **可拍演示及教学**：声音/方向过关后，完成两音色、短句、逐音教学，再按三分钟脚本拍摄；AI转换先核对结果再导入。
6. **量化验收**：七区/漂移→≥4Voice→32Voice/音效→1000次延迟→2小时满载，保留全部原始数据。原10ms目标需先确认是否接受按钮模式及其计时起点，必要时优化消抖并重做回归。

## 本次交付边界

本次归档保持V14冻结功能，没有新增双MPU、音量80、动作击发、无漂移或“已修复无声”的声明。上传和仓库清理不是新硬件验收。清理前冻结成果可从标签恢复，详见[版本清理与恢复](版本清理与恢复.md)。
