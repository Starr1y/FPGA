# DUO03：统一控制与菜单接入

2026-10-17。工程 `fpga/duo03/tanglab_duo03.gprj`，顶层 `top_duo03`。这是新的整机候选；DUO02、DUO01、FAN04 保持冻结。是否已有可发布位流，以 `board-test/duo03/firmware.json` 和对应 SHA256 为准，编译开始或有局部报告不代表构建通过。

## 本版连接的功能

- 板载键、外部编码器、踏板和左右腕部按钮汇入同一份 `duo_parameters` 状态，音色、尾音、布局、当前手、模式、静音和音效没有各自独立的副本。
- 两个 BNO085 沿用 DUO02 的独立 I²C、相对归中、前方 180° 非循环 7/5/12 选区、负 Z 线性加速度 **或**负向急动度击发。取消距离选区的决定继续有效。
- 共 32 Voice；接受音符时锁存音色/尾音，左手和弦和右手旋律仍有独立所有权。原传感器事件队列到合成器的 epoch/release 握手保持单份。
- 菜单设置驱动真实立体声音效：延迟、反馈、湿声和合唱深度；结构调参先降低湿声、切换并清除历史，再恢复。菜单同时显示当前生效音效和“过渡中/已生效”，列表显示请求值。
- 同一个 1024 位帧快照承载演奏状态、菜单目标和实际音效状态；演奏、诊断、菜单在消隐期间切换。两绘制器共享时钟和光栅时序，没有全屏帧缓存。
- 字体沿用文楷 20 px，中文 24×24 字格、不膨胀字形；主界面保持双扇区和隐藏遥测。仍为原生 640×480、25 MHz，不代表多分辨率或 EDID 已完成。

## 板载键与菜单

主页面沿用 DUO02 的按键含义。所有动作在合格松键后执行；上电先稳定松开全部按键，复位期间一直按住的组合不会在随后松开时意外启用 IMU。

| 操作 | 主页面 | 菜单打开时 |
| --- | --- | --- |
| KEY0 短按 | 当前手归中 | 进入/退出编辑 |
| KEY0 长按约 1.5 秒 | 当前手切换 7/5/12 音区 | 从编辑返回选择；再长按关闭菜单 |
| KEY1 短按，少于 300 ms | 当前手轮换音色 | 下一项；编辑中增加 |
| KEY1 按住至少 300 ms | 当前手表情，松开结束 | 不触发表情或修改音色 |
| KEY2 短按 | 切换操作手 | 上一项；编辑中减少 |
| KEY2 长按约 1.5 秒 | 复位当前手 | 仍复位当前手 |
| KEY0＋KEY1 短按 | 打开菜单 | 关闭菜单 |
| KEY0＋KEY1 长按约两秒 | 双旋律/左和弦右旋律 | 同左 |
| KEY1＋KEY2 短按 | 演奏/诊断切换 | 关闭菜单，切换诊断 |
| KEY1＋KEY2 长按约两秒 | 启停当前手 IMU | 同左 |
| KEY0＋KEY2 长按约两秒 | 静音切换 | 同左 |
| 三键同时短按 | 湿声简易加档 | 同左 |
| 三键同时长按约两秒 | 旁路→延迟→合唱→混响 | 同左 |

编码器旋转选择或调整，短按进入/退出编辑，长按返回。首次短按只打开隐藏的菜单。菜单中的“操作手”编辑与主页面 KEY2 使用同一状态；两边修改音色也会互相反映。KEY1 表情的手归属在按下时锁存，菜单打开会抑制表情。

外部踏板在合格松开时切换演奏模式；两只腕部按钮各自短按归中、长按换区，短按归中只作用于已使能的那一手。共享参数发生同周期冲突时，板载动作优先；踏板优先于编码器对模式项的编辑，腕部动作仍以自己的手为归属。

## 新增控制输入接线

以下是 NEO Rev1.4 原理图第 7、19 页的逐点追踪，尚未做外部实体输入验证。使用排针编号和球位核对，不以照片中的左右朝向推断。

| FPGA 输入 | 球位 | SOM 连接器 | 网络 | Dock 接点 |
| --- | --- | --- | --- | --- |
| 编码器 A | E14 | J1.65 | SDRAM0_D0 | J13.1 |
| 编码器 B | E13 | J1.67 | SDRAM0_D1 | J13.2 |
| 编码器按下 | C15 | J1.59 | SDRAM0_D2 | J13.3 |
| 踏板 | C14 | J1.61 | SDRAM0_D3 | J13.4 |
| 左腕按钮 | B13 | J1.53 | SDRAM0_D4 | J13.5 |
| 右腕按钮 | C13 | J1.55 | SDRAM0_D5 | J13.6 |

六根线均为 Bank 2 LVCMOS33 **输入**，启用内部弱上拉，空闲为高。无源编码器公共端、无源按键和踏板的公共端接同一 GND；常开触点闭合时把对应输入接地。GND 可使用已核对的 J13.12。编码器 A/B 若方向相反，可在断电后交换这两根信号。默认每定位 4 个合法边沿；2 边沿编码器需要修改参数并重新构建。

这些端口按无源触点设计，不把外部模块的 5 V 输出接入。J13.11 是 **5 V**，不是这些信号的供电点。没有接外部按钮时可以全部留空，板载键提供菜单备用操作。

两颗 IMU 的原接线与供电要求见 [DUO01 引脚追踪](DUO01_双手板卡接入与操作.md)；D14/D15/F15 继续留空。不能把 GPIO 当供电，手动启停没有新增 PGOOD、限流或掉电隔离。

## 数字检查与构建

```powershell
python -X utf8 fpga/tools/check_duo03_controls.py
python -X utf8 fpga/tools/check_duo03_audio.py
python -X utf8 fpga/tools/check_duo03_video.py
python -X utf8 fpga/tools/check_duo03_board.py

python -X utf8 fpga/tools/package_duo03.py
python -X utf8 fpga/tools/duo03_release.py verify
```

检查分别覆盖原始控制电平与上下文、分配器 8/32 Voice/背压/取消、完整帧快照与光栅、真实 50 MHz/48 kHz 双 I²C 行为模型至 DAC、板卡顶层原始按键/编码器至 RGB。行为传感器与 PCM 不能替代实物姿态和模拟声音；光栅检查跳过厂商 PLL/TMDS 原语，原始控制到画面检查缩短按键时长，原生传感器链路使用强制参数激励，范围各自记录在 JSON 中。

本版将分配器动态索引的 revision 增量改成各 Voice 本地增量，用于缩短选择与写回路径。是否改善时序只看本版最终布局布线结果，不用 RTL 变化或仿真周期数推断 Fmax。构建与打包仍要求 50 MHz 核心、25 MHz 像素、setup/hold 零违例，没有降低频率或删除时序门槛。

## 实物和完整任务边界

当前没有新版本的下载、真实两颗 IMU、外部按钮、听音、模拟延迟、识别率或两小时满负载证据。先单颗健康模块验证，再扩双手；实测仍按 [任务书执行与验收](当前任务书执行与验收.md)逐项记录。Voice/波形/频谱显示、WS2812 教学和原生多分辨率仍在完整任务范围内，不能因为菜单接入而算作完成。
