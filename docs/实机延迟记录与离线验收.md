# 实机延迟记录与离线验收

2026-10-17。本文件准备任务书 T5 的记录方法和统计入口。当前没有新实测数据，空模板和分析器自身检查均不构成延迟验收完成证据。

## 测什么

同一仪器同时记录外部动作参考与 **DAC 模拟输出**。参考可以是接触、光电、力或外部运动传感器；写明它表示下拍过程中的哪个时刻。接收 IMU 报告、产生 FPGA Note-On、UART/USB 收到消息等时间可以用于数字调试，不能代替外部动作参考到模拟输出的整机测量。

每条记录保留参考与模拟起音在同一采集时基中的时间。先确定起音阈值、噪声基线、持续样本数、音色、力度及触发方式，保存方法，再开始采集；不能看过结果后逐次换阈值。不同音色的 Attack 会影响模拟起音位置，需要在原始记录中说明。左右声道的模拟接点、参考通道与手的对应关系也必须能在波形中复核。

任务书目标为至少 1000 次、最大值不超过 10 ms；原始异常和漏触发都保留。单手测试可以先完成，但不能据此申报双手整机完成。按每手至少 500 条组织双手数据，避免只测一手而自动给出双手结果。

DUO03 当前在 `bno_i2c_host.v` 中请求 10,000 μs 报告间隔。若实际触发数据也按 10 ms 周期到达，仅采样相位就可能接近 10 ms，还要加上传输、解析及音频起音时间，因此 FPGA 时序通过不能证明整机最大延迟达到目标。须先测实际报告周期与外部动作延迟；需要增加余量时，再调整触发数据报告率并重做总线负载、时间戳和击发回归。当前没有这项实测结论。

## 记录文件

复制 `board-test/hardware-acceptance/template/` 到一次独立实验目录，在其下建立 `raw/`，保存仪器原始导出文件。模板没有示例成功数据；`measurement_kind` 初始为 `unrecorded`，填写真实实验后改为 `physical`。

CSV 必须包含以下列，时间单位统一为非负整数纳秒。每次外部参考动作有一行，ID 唯一。

| 列 | 含义 |
| --- | --- |
| `trial_id` | 全实验唯一试次编号 |
| `hand` | 0 左手，1 右手 |
| `reference_ns` | 原始采集文件中外部参考的时间 |
| `onset_ns` | 同一时基中的模拟起音时间；漏触发留空 |
| `outcome` | `hit` 或 `missed`，没有“排除”类别 |
| `trace_file` | 相对本实验 `raw/` 的文件路径，可多行指向同一个分段采集文件 |

不要只保存软件截取的“通过样本”列表。漏触发仍有参考时间、原始采集文件和 `missed` 行。`session.json` 的 `reference_count` 写全部外部动作数，必须与 CSV 行数一致。空行不代表漏触发。

会话 JSON 还应填写仪器、采样率、通道、外部参考种类、模拟起音判据、实际烧录 FS 的 SHA256，以及每个原始文件的 SHA256。`same_instrument_timebase` 只有在两个时间标记使用同一采集时基时才填 `true`。不比较 PC 与示波器各自的墙钟时间。

## 运行统计

```powershell
python -X utf8 fpga/tools/analyze_motion_latency.py `
  board-test/hardware-acceptance/实验目录/latency.csv `
  board-test/hardware-acceptance/实验目录/session.json `
  --firmware fpga/bitstream/tanglab_duo03.fs `
  --output board-test/hardware-acceptance/实验目录/latency-assessment.json
```

上面的位流路径必须换成**实际使用**的冻结版本；DUO03 只有完成编译、时序和打包后才可使用对应文件。这个工具只处理已有文件，输出全部样本计数、分手统计、最小/平均/中位/95%/99%/最大延迟，以及超限和漏触发数量，不参与 FPGA 的演奏链路。

纳秒先按整数比较，10,000,000 ns 合格、10,000,001 ns 超限，不用显示精度把超限值舍去。百分位使用 nearest rank。重复 ID、负延迟、NaN、损坏 CSV、未知手、动作数不一致会使整份记录无效，不从剩下的“好行”生成成功结论。原始文件或位流哈希不匹配时，证据完整性不通过。

分析器对自动进入波形复核采用保守门槛：至少 1000 条、两手各至少 500 条、没有漏触发或超限。若有漏触发，仍输出已观测起音的统计和完整分母，但不给出自动数值通过；这不把任务书独立的“识别率 ≥98%”改成 100%，识别率及漏触发与延迟数据的验收口径仍需单独复核。

## 结果含义

| `assessment` | 含义 |
| --- | --- |
| `INVALID_INPUT` | 记录格式或方法信息不足；退出码 2 |
| `NUMERIC_FAIL` | 数值门槛未达到，保留全部数据；退出码 1 |
| `EVIDENCE_INCOMPLETE` | 数值达到门槛，但缺原始文件、哈希不符或缺实际位流对照；退出码 1 |
| `SYNTHETIC_ONLY` | 分析器测试数据，不能申报实测；退出码 1 |
| `READY_FOR_TRACE_REVIEW` | 数值及文件完整性检查通过，进入人工原始波形复核；退出码 0 |

工具始终输出 `physical_verified: false`。会话自报 `physical`、正确哈希或退出码 0 都不能证明动作参考真实、模拟起音标注正确或整机延迟已经验收。最终需核对原始波形、接线、仪器设置、实际下载版本与全部异常，形成有明确范围的实测结论。

此统计不覆盖每人每手 100 次识别、100 次非击打误触发、10 分钟漂移、32 路谱峰/静音或两小时满负载；这些仍按完整任务书记录。
